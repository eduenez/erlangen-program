# The Erlangen Program, Concretely

A sequence of self-contained, interactive lessons on groups of geometric
transformations — an accessible, modern introduction to the philosophy
behind Klein's *Erlangen Program*: a geometry is defined by its group of
transformations, and different groups (isometries, similarities, affine
maps, projective/Möbius maps) give genuinely different geometries on the
same underlying space.

Each lesson is purely mathematical: no course, institution, schedule, or
grading context of any kind. Every lesson is licensed
[CC BY 4.0](LICENSE) — copy, adapt, and reuse freely with attribution.

## Status

Early stage. The first lesson (discrete groups generated by one or two
translations) was originally prototyped as a Jupyter/ipywidgets/Plotly
notebook, then rebuilt as a standalone JSXGraph page once it became clear
that lesson involves no code students would ever touch. Both `web/` pages
have since been rebuilt again, on a dependency-free WebGL2 fragment shader
with a Canvas-2D overlay: coloring a fundamental region *continuously* and
reproducing that coloring faithfully on every translate is an inverse
problem solved per pixel, which is what a shader does and what an SVG
library cannot do at interactive rates. The default going forward is
**a self-contained page in `web/`**, unless a specific lesson has a genuine
argument for real Python/SageMath code (e.g. something students should read
or modify, not just parameters to drag).

- `web/` — standalone HTML/JS pages, no libraries of any kind. Open
  directly in any browser, from disk, with no kernel, install, or network.
- `notebooks/` — kept as infrastructure (the generator-script toolkit,
  `notebook_toolkit.py`) for any future lesson that does need real code.

## Planned lesson sequence

1. **Discrete groups with one or two generators** — translations, and the
   isometry groups of the square and hexagonal lattices.
2. **One-parameter groups** — translations along a line, rotations,
   "spiral" groups ($z \mapsto e^{at} z$).
3. **Linear and affine transformations of the plane.**
4. **Möbius transformations of the extended complex plane** — orientation-
   preserving first, then reflections/inversions.
5. **The Riemann sphere** — stereographic projection, and the same Möbius
   group realized as transformations of $S^2$.
6. **Groups as matrices, matrices as actions** — the formal notion of a
   group action, motivated by the matrix representations used above.

Lower priority, time permitting: isometries/similarities/affine maps of
3-space; projectivities of the real projective plane.

## Development setup

    make venv       # creates .venv/, installs requirements.txt, registers
                     # a "python3" Jupyter kernel scoped to .venv (won't
                     # clash with any other "python3" kernel on the machine)
    npm install      # only needed for the web/ page tests (Playwright)

Everything below assumes `.venv` is set up; nothing installs system-wide.

## Building a notebook

Each notebook has a generator script in `notebooks/` (e.g.
`build_lattice_groups.py`) — run it with `.venv/bin/python3` to
(re)produce the `.ipynb`.

## Testing

    make test             # both of the below
    make test-notebooks   # executes every notebooks/*.ipynb top to bottom,
                           # fails on the first error
    make test-html        # drives every web/*.html page with a headless
                           # browser (Playwright) and checks the results

`test-notebooks` only exercises the *default* widget state — running a
notebook top to bottom isn't the same as dragging every slider, since
`ipywidgets` callbacks fire in response to live front-end events that batch
execution doesn't simulate. Treat it as "the code has no bugs on load," not
"every slider position was checked." The actual math each widget calls into
should be covered by its own plain (non-widget) test — see how
`build_lattice_groups.py`'s `lattice_points`/`cyclic_points` functions were
verified against known cases before ever being wired to a slider.

`test-html` has no such limitation — Playwright drives the real page,
setting generators through each page's console interface (`lattice.setA`,
`spiral.setA`, …) and dragging with real pointer events. Besides the
interaction rules, it reads pixels back off the WebGL canvas and checks the
property the lessons rest on: points of a common orbit must receive the
*identical* color, and points of distinct orbits must not.

## Algebra and geometry exhibits

`web/algebra-geometry/` is the canonical home of six reusable exhibits:

- `intersections.html`: circle/line intersections, tangency, nonreal roots,
  and the projective intersection of parallel affine lines.
- `bezout.html`: line/cubic, two ellipses, two circles, and a vertical line
  with a parabola; real, nonreal and infinite intersections always total the
  product of the degrees.
- `desargues.html`: perspective triangles in two spatial planes and the same
  configuration after central projection; in the planar view the vertices can
  be dragged.
- `arithmetic.html`: sum and product of points of a line by parallels, and
  commutativity as Pappus's theorem.
- `branching.html`: continuous square-root tracking around a branch value.
- `exponential.html`: the map `z -> e^z`, its period, and the infinite fibres
  behind the proof that it is a transcendental function.

Open `web/algebra-geometry/index.html` directly from disk. This group shares its
own local `style.css` and `exhibits.js`; all files stay together, and no network
or third-party library is needed. The Pages workflow uploads this directory
with the rest of `web/`, giving the canonical public home
`https://supernumero.us/erlangen-program/algebra-geometry/` after deployment.
The root lesson index links to the group.

These sources belong here, independently of any talk or course using them.
The reusable Beamer sources and figure generators live in `talks`; courses keep
only frozen slide PDFs and link to the demonstrations.

Run `npm run test:algebra-geometry` for the group's Playwright checks; `npm test`
also includes them. `PLAYWRIGHT_CHANNEL=chrome` selects installed Chrome when
needed; otherwise the standard Playwright Chromium is used. `QA_DIR` can set
the screenshot output directory (the default is under the system temporary directory).
